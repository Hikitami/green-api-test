# Развёртывание

Адрес приложения: http://194.31.204.81:8081

На сервер загружается только содержимое `dist`. Статику раздаёт отдельный контейнер `green-api-web` на порту 8081. Настройки домена и контейнеры StudyPlatform не используются.

## Размещение

- Релизы: `/opt/green-api/releases/<commit>`.
- Текущая версия: символическая ссылка `/opt/green-api/current`.
- Контейнер: `green-api-web`, образ `caddy:2-alpine`.
- Публикация: порт сервера 8081 → порт контейнера 8080.
- Перезапуск после перезагрузки сервера: `unless-stopped`.
- Файлы смонтированы только для чтения. Сборка выполняется локально, Node.js на сервере не нужен.

## Обновление

1. Выполнить `npm run check`.
2. Упаковать сборку: `tar -czf release.tar.gz -C dist .`.
3. Загрузить архив по SSH в `/opt/green-api/releases/`.
4. Распаковать его в новый каталог релиза.
5. Переключить ссылку `current` на новый каталог через `ln -sfn releases/<commit> /opt/green-api/current`.
6. Проверить страницу и деморежим. Контейнер перезапускать не нужно: смонтирован родительский каталог, а не отдельный релиз.

Для отката переключить `current` на предыдущий проверенный релиз.

## Обслуживание

Команды выполняются на сервере:

```bash
docker ps --filter name=green-api-web
docker logs --tail 50 green-api-web
docker restart green-api-web
```

Сервер отдаёт приложение по HTTP согласно выбранному варианту размещения. Демо не требует секретов. Для работы с реальными токенами лучше использовать HTTPS: HTTPS-запросы к GREEN-API не защищают саму страницу, если она загружена по HTTP.

Генерация ID использует `crypto.getRandomValues`, поэтому сообщения работают и на HTTP-адресе. Браузерные тесты можно выполнить против сервера, задав `E2E_BASE_URL=http://194.31.204.81:8081`.
